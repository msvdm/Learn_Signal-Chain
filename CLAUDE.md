# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## The #1 Rule

**This app is for beginners in sound engineering.** Every label, tooltip, warning message, and UI element must be understandable by someone who has never touched a mixing desk. Avoid jargon without explanation. Prefer plain English over technical accuracy when both are possible. If a concept needs a number (e.g. dB), always follow it with a plain-language consequence ("−60 dBu — very weak, too quiet to use").

a gate starting closed, opening on the peaks, Hold then Release, set between the noise and the music; a limiter's ceiling on every sample; a split-band de-esser taking a high tone down and leaving a low one alone; the meter's peak, average and hum over its stretch, and how the signal moves slice by slice (blocks ending one slice and starting the next). `src/audio/meters.test.ts` — the meters' movement as a DAW's meters move (D10): the RMS over 300 ms (a sine its average everywhere, 3 dB under its peaks; rising over 300 ms; the loop's start hearing its end), the peak (at once, then 20 dB down in 1.7 s, into the loop's start), the hold (3 s, then falling; a louder peak takes over), the Generator's sine (peak and RMS almost touch) against its clicks (far apart on every beat), turning down (in against out, makeup back in, never below 0, silence 0), two sides as one, slices turned round to the loop's start. `src/signal/moving.test.ts` — that movement between a change and the next render (`liveStageOf`: as rendered; a fader turned: moved by the number engine's step at once; switched to stereo, or silent now: still; the hold never under the peak). `src/audio/sounds.test.ts` — the Generator's sounds (a loop long, an RMS of 1, `PEAKS_ABOVE`; clicks silent between beats) and the hiss (adds up as powers). `src/utils/chainFile.test.ts` — what a source picks up, from today's files and older ones (`melodic` / `percussive`). `src/utils/mainFader.test.ts` — a Limiter on a stereo bus's L takes the whole mix (L and R out, a Fader after it the Main Fader, both speakers moved onto it, an older save settled the same way), a stereo channel through one stays one wire. `src/graph/queries.test.ts` — a source not connected yet (`unwiredSource`, decision D11: every kind alone, wired, a Microphone hearing a Guitar Amp with nothing on its own output; never anything but a source). The render on real sound itself (`audio/measure.ts`) and the moving meters are checked in the browser: Web Audio does not run in Bun. They lock today's levels: a change to the engine that moves an old chain's average fails them. A reading changed on purpose is updated in the table, with the reason in a comment. `npm run test:node` runs the same files with Node: `test/node-hooks.ts` resolves extensionless imports and swaps `bun:test` for `test/bun-test.ts` (a stand-in with only the matchers the tests use — add one there before using it). `tsconfig.test.json` type-checks the tests (part of `bun run build`); the app's build leaves them out. The UI has no tests: check it in the browser.

## Working on this project

**How the work goes** (the user's way of working):
- Work happens on `master`: the user is the only developer, so no branch for a piece of work (2026-10-06, the user's call) — only when they ask for one. Start with `git fetch` and check `master` is the remote's latest (a reused cloud container once started a session on a stale local branch); a session that finds itself on another branch (a cloud session's own) says so at the start, so its work doesn't end up off `master`. A piece of work: build it, `bun run lint` + `bun run build` + `bun test`, check it in the browser, update this file where it changed, commit — and tell the user what was done, the numbers measured, the choices made (to review) and what only they can check. One commit per step.
- **Push only when the user says so.** "Push" = push `master`: GitHub runs `.github/workflows/build-check.yml` (lint, test, build) and deploys nothing. "Push and release" = push, then the next version tag (`git tag v0.2.0 && git push origin v0.2.0` — see `git tag`, propose the number: v0.x.0 for features, v0.x.y for fixes; the first was v0.1.0): only a `v*` tag, or *Run workflow* in the Actions tab, runs `deploy.yml` to GitHub Pages (its `github-pages` environment allows `master`, `gh-pages` and `v*` tags). `package.json`'s version stays 0.0.0. - **The user decides what the app teaches and how it looks.** When a decision is theirs — or real behaviour breaks the premise of one they made — ask, with a recommendation, before building around it (D8, D9 and D10 were asked that way, D11 with mock-ups).
- **Prefer what the browser already does** (Web Audio and the like) over homemade simulations, and say so up front; flag it early when a step's code grows far beyond its plan (decision D7 came from a 1,600-line homemade time engine).
- **Real sound can change a lesson**: measure, then rewrite the help text (en + bg) — never tune a processor to fit an old sentence. Every number a text quotes is checked against the number engine or a render (see below).
- **No new packages so far** (the Vite plugins are written here). CI installs with `bun install --frozen-lockfile`, so a package needs `bun.lock` updated in the same commit — ask the user first.

**Environment**:

Its fonts (Inter, DejaVu Sans Mono) are close to, not the same as, the user's, and it paints in software. Keep the browser-only code thin, test what is pure, and leave the user an exact list of what only they can check (the step's *Left for the user*: their devices and fonts, how it feels), with what they should see.

**Checking in the browser** (the console tricks work in any browser):
- `await import('/Learn_Signal-Chain/src/store/signalStore.ts')` gives the live store: `useSignalStore.setState({ nodes, edges })` builds a chain (a node: `{ id, typeKey, position, params: initialParams(typeKey, level), bypassed: false }` — `initialParams` from `src/data/nodeRegistry.ts`; a wire: `{ id, source, sourceHandle: 'out', target, targetHandle: 'in' }`). After a hot reload the app runs `signalStore.ts?t=<time>`: import the URL it loaded (`performance.getEntriesByType('resource').map((e) => e.name).find((n) => n.includes('signalStore.ts'))`), or you get a second, empty store. `setState({ nodes, edges })` skips `commitGraph`: where a Main Fader, a Graphic EQ or an Amplifier must take L / R over, add the elements with the store's `addNode` / `addEdge` instead.
- Real sound from the console: `stillPicture(nodes, edges)` (`src/signal/engine.ts`) → `measureChain(still.plans, still.levels)` (`src/audio/measure.ts`) → `withMeasured(still.result, { at: still.result, ...m })` (`src/signal/measured.ts`) is what the cards show. Time a render with `performance.now()` around `measureChain`.
- Wiring needs real mouse events (mousedown → mouseup → click: a dispatched event misses the bug class "the click after the press undoes it"); hover a port ~0.4 s first — Connect mode comes on hover. A palette drop can be dispatched: `dragover` + `drop` events with a `DataTransfer` holding `application/lsc-node-type`.
- The production build and the one-file copy cannot import modules: open a chain there with a share link made in the dev app (`encodeChain(toChainFile({ nodes, edges, outEdges: [], sizes: {} }, name, level))` from `src/utils/chainFile.ts` → `…#chain=<encoded>`) and read the cards' text.
- To try a processor idea outside the browser, decode a loop (`ffmpeg -i src/audio/loops/speech.mp3 -f f32le -ac 1 -ar 48000 speech.f32`), skip 12000 samples (`PAD_S`), take 480000 (one loop), and run a copy of the processor on it with Bun.
- Editing the locales by script: `json.load` + `json.dumps(indent=2, ensure_ascii=False)` + a final newline round-trips both files except `levelNames.intermediate`, written on one line — put it back (or replace the text in place).
- A refactor that must change nothing: snapshot HEAD's `src` (`git archive HEAD src | tar -x -C <dir>`) and compare old and new engine results over many random graphs built through the connection rules; tag graphs with wires the app forbids — they explain most differences.

## Architecture

The app is a **pure client-side React SPA** — no backend, no API calls. The signal is worked out in the browser twice: at once by the number engine (arithmetic on levels, `src/signal/`), and a moment later by a silent render of the chain on real sound (Web Audio in an OfflineAudioContext, `src/audio/`), whose readings the cards show (decision D9). The render also records how every card's signal moves over its loop, and from Intermediate the meters play that back (decision D10).

### Offline (no extra packages)

`vite-offline.ts` (a Vite plugin, build only) adds two files to `dist/`:
- **`sw.js`** — a service worker listing every file of the build (its cache name is a hash of that list). It keeps them all on the first visit; the page itself comes from the network first and falls back to the kept copy, everything else from the copy (file names carry a content hash, so a copy is never stale). `main.tsx` registers it in production over http(s) only. After one visit the site opens with no internet, and browsers offer to install it (`public/manifest.webmanifest`, icons `public/icon*.png` / `icon.svg`).
- **`learn-signal-chain.html`** (`OFFLINE_FILE`) — the whole app in one file: the script and styles inlined, the icon as a data URI, the sound loops (`src/audio/loops/*.mp3`, ~620 kB) as data: URLs in the script (the file is ~1.6 MB). The AudioWorklet's code is in the script as text anyway (`vite-worklet.ts`: `processors.ts?worklet`, handed to the worklet as a Blob URL). File → *Download the app…* saves it; double-clicked, it runs from disk. The build fails if the bundle ever has more than one script chunk, a stylesheet loads a file (`url(…)`) or the script loads a file of `assets/` it does not hold — the one-file copy could not have them.

A copy running from disk (`location.protocol === 'file:'`) hides *Download the app* and makes share links point to `ONLINE_URL` (`src/data/site.ts`). Test the offline parts with the `preview` launch config (production build on port 4173) — the dev server registers no service worker.

### Interaction model (SmartDraw-style)

The canvas works like a drawing app and **follows the mouse** — there is no mode toolbar and no mode keys:
1. **Left palette** (`ElementPalette`) — search, category tabs, 2-column tiles, all one size (`TILE_H`: the icon and a name on up to two lines, a long one — Bulgarian's — on three in smaller letters, `tileName`), in the order a signal meets them (`NODE_LOOK`; the user's layout of 2026-10-06, row by row: Processing runs Gain, Analog to Digital Converter, HPF, Pad, Gate, EQ, Compressor, Limiter, De-esser, Graphic EQ, Digital to Analog Converter) (an icon rail at tablet width ≤ 1024px). It slides **over** the canvas (absolute, `z-index` 20; the canvas wrapper is `isolation: isolate`), so nothing on the canvas moves when it opens; the bottom-left tools step out from under it (`--lsc-palette-w` on `<main>`, `.lsc-left-tools`) and "show everything" pads its left side by the palette width (`useFitView`; the width is `usePaletteWidth`). Drag any tile onto the canvas; the node lands where it is dropped (cursor on its port line), nudged only to avoid overlapping another node. Dropping a node with an input and an output onto an existing wire inserts it mid-chain when both new wires could be drawn by hand (`wireTakesCard`; otherwise it is placed unwired where it was dropped; the drop preview snaps to the slot): once the new card is measured, the rest of that chain slides right — other chains stay put — and if the card is tall, everything under it (cards, and wires running there) moves down as one block.
2. **Select mode** (`toolMode: 'select'`, the default) — what a left-click does then follows the **left-click tools** (`CanvasTools`: one row of icons right of the zoom controls — hand · dotted square · eraser, then Undo · Redo; the name, shortcut and a line of help pop up on hover; `leftTool` in the store):
   - **Drag** (default) — drag nodes, pan the canvas, click a card's empty part to select it (Ctrl+click adds, Shift+drag draws a box).
   - **Select** — a click on an element's empty part adds / drops it, dragging empty space draws a selection box (`SelectionMode.Partial`; the middle button pans). React Flow's box around a selection is hidden (CSS).
   - **Selecting is ours, not React Flow's** (`useCanvasClicks`): `selectFromBox` takes React Flow's select changes only while its selection box is drawn (`userSelectionRect` is set); clicks go through `onNodeClick`, which ignores a press that started on a control or port (`INTERACTIVE`: `.nodrag`, buttons, inputs, handles — judged at `pointerdown`, since a knob drag that ends off the knob clicks the card) or that moved. Dragging never selects: dragging an element of the selection moves the selection, dragging any other element moves only it and drops the selection (`onNodeDragStart`).
   - **Remove** — a click on an element (anywhere on it, even a knob — handled on capture-phase `pointerdown`, `useCanvasClicks`) or a wire removes it; hover shows red. No wiring in this tool.
   A dragged selection moves together (`moveNodes`, wires between them take their bends along). Selection lives in `selectedNodeIds`; selected elements get a solid accent ring, a glow and a tint (thicker in overview).
3. **Connect mode** (`toolMode: 'connect'`) — entered automatically when the cursor is over a port; it switches back to Select ~200ms after the cursor leaves all ports, never while a wire is being drawn and never while a mouse button is held. Wiring uses a **click-once pen-tool interaction, never drag** (`useWireDrawing`; the wire being drawn — source, start, corners — is the store's `wire`, only its loose end at the cursor is the hook's):
   - **Click once** on an output port → wire begins; a "Connecting from …" toast appears and valid free inputs pulse
   - **Move freely** → a dashed orthogonal (right-angle-only, rounded corners) preview routes live to the cursor
   - **Click in empty space** → commits a corner waypoint, locking that segment; routing continues from the waypoint
   - **Click a highlighted input** → completes the connection (a snap ring appears on hover to confirm the landing point)
   - **Right-click or Esc** → cancels the wire in progress
4. **Delete a connection** — hover a connected **input** port → the port itself turns into a red × (whenever no wire is being drawn) → click it. Outputs never turn into ×: clicking an output always starts a new wire, so one signal can feed several inputs.
5. **Reshape a wire** (Intermediate / Advanced) — wires with bends show drag handles on their corners and segment midpoints, in either mode (`CanvasOverlays`: each handle has its own `onPointerDown` and the `lsc-overlay` class, so the press never reaches the wiring).
6. **Esc** cancels a wire in progress, otherwise closes the help popover, otherwise drops the selection (`useCanvasShortcuts`).
7. **Zoom** — mouse wheel / trackpad, or the React Flow `<Controls>` (zoom in / out / fit) at the bottom-left of the canvas.
8. **Overview** — zoomed out below 42% (back above 50%: hysteresis, `OVERVIEW_ENTER_ZOOM` / `OVERVIEW_LEAVE_ZOOM` in `SignalChain.tsx`), every card swaps its controls for its name, as big as it fits, and the level leaving it (sources and speakers keep their face: a big icon, no level — see Node card shell). Free-standing controls stay as they are. Wires are drawn thicker. Wiring, dragging and unplugging work as usual.
9. **Right-click menu** (`NodeMenu`) on any element: What is this? (help popover) · Bypass / Turn back on (types that can be bypassed) · Cut · Copy · Duplicate ← → ↑ ↓ · Remove. Right-clicking an element of a selection acts on the whole selection ("3 elements selected", no Help / Bypass); otherwise that element becomes the selection. The empty canvas has its own menu (`CanvasMenu`): Paste here · Select everything · Insert a saved chain here… (see Save / Open). Keys (`useCanvasShortcuts`; not while typing in a field — `typingInField` in `utils/shortcut.ts` — or in an open menu or `role="dialog"`): Ctrl/⌘ + C, X, V (at the mouse), D (duplicate right), A, Z (undo), Shift+Z or Y (redo); Delete / Backspace removes the selection. Cut / copy / paste / duplicate / remove and placing a copy are `useGroupActions`. Copies (`utils/nodeGroup.ts`) take the wires between the copied elements and their wires into a bus input that takes many (a copied channel joins the same mix); a copied source gets its own chain colour; the copy lands beside the original, clear of other cards. There are no ? or × buttons on the elements; a tip at the bottom of the palette points to the menu. A right-click while a wire is drawn only cancels the wire (the capture-phase handler stops the event).

Every level starts from a **blank canvas** at 100% zoom (also after File → New, a level change or removing the last node). The canvas is **autosaved** and comes back after a refresh, fitted on screen (see Save / Open). There is no preset layout, no fixed Master Bus and no position restrictions. Levels control which node types appear in the palette, not the graph structure.

### Save / Open

One format everywhere — `ChainFile` (`utils/chainFile.ts`): `{ app: 'learn-signal-chain', version, name, level, nodes, edges, sizes }` (`sizes` = card sizes when saved, so the chain can be placed before it is measured).
- **Autosave**: the store writes it to `localStorage` `lsc-canvas` 300ms after the last graph / name / level change (and on `pagehide`); at start the canvas and its level come back from it.
- **Save to a file** / **Save as a picture** ask for a name first (`chainName`, suggested next time) and download `<name>.json` / `<name>.png`. The picture (`html-to-image`, pinned 1.11.11 as in React Flow's example) is `.react-flow__viewport` drawn at zoom 1 with the canvas colour; while it is taken `capturing` turns the overview off and the selection / highlights are cleared — it waits until the DOM shows none of them (`NOT_IN_PICTURE` in `useChainFile.ts`), then for the overview crossfade. The chain rides inside the PNG as a `tEXt` chunk (`lsc-chain`, `utils/pngText.ts`).
- **Share link**: `<app>#chain=<deflate-raw + base64url of the JSON>` (`encodeChain`), copied to the clipboard; a link longer than 8000 characters gets a warning. Opening one (at start or `hashchange`) clears the hash first, then offers the chain.
- **Opening** (File → Open, Ctrl/⌘+O, a share link) reads a `.json` or a picture saved by the app (`readChainFrom` — anything else gives a plain-language notice) and sets `chainOffer`. An empty canvas just loads it; otherwise `ChainOpener` asks: **Replace the canvas** (`loadChain`: the file's ids and colours, its level — one undo step at the same level, a new history at another) or **add it beside** with the Duplicate arrows ← → ↑ ↓ (`besideOffset`, then `placeCopy` in `useGroupActions` → `cloneGroup` / `addGroup`: new ids and chain colours; `raiseLevel` goes up to the chain's level if it is harder, clearing nothing).
- **Insert a saved chain here…** (canvas right-click) and a `.json` / `.png` **dropped on the canvas** add the chain at that point (`pasteOffset`), no question.
- `parseChainFile` keeps only what the app can show: unknown element types (a newer version) and their wires are left out (counted, "N elements were left out"), saved params go over `initialParams()` (an older file gets new knobs), a value of the wrong kind — or a word a setting does not know for that type (`paramChoices`) — falls back to the default. Words of older versions are read as today's (`OLD_WORDS`: a Microphone's or Line Input's `melodic` is its default, Speech / Music; `percussive` is Drums).
- Results and problems show as a bottom-centre notice (`notice` in the store, `NoticeToast`).

### Data flow (read this first)

```
signalStore (Zustand)
  ├── nodes[] + edges[]  (graph model — user-built, freely positioned)
  │     ├── src/graph/   what the wiring makes of it: ports, what each wire carries, Main Faders, Preamps …
  │     └── src/signal/  the number engine: walks the graph in signal order, the levels at every card / wire
  │           ├── chain.ts      planChain(): what the wiring makes of each card (once per change); runChain(): its levels
  │           └── engine.ts     stillPicture(): plan + levels at once, on every change · graphSignal(): that picture with
  │                 │           the last render's readings put in (signal/measured.ts) — shared by every card
  │                 └── useStage(id) / useWire(key): each card reads only its own result
  └── measured  ← store/measuring.ts: once a change has settled, the chain is rendered on real sound
                  (src/audio/: the same plan as Web Audio nodes, our processors in an AudioWorklet, the loops)
                  and every card measured — peak, average, noise, hum — and how it moved over the loop
                    └── hooks/useLiveMeter.ts: one animation loop, outside React, plays that movement back
                          into the meters, the turning-down bars and the curves' marks (30 pictures a second)
```

Every slider change → updates `signalStore` → the number engine recomputes at once and the readings move by its step from the last render → 100 ms after the last change a render starts; when its readings arrive (~30–500 ms on desktop) they replace the step → the cards and wires whose own reading changed redraw; the rest are left alone. There is no local component state for signal values.

**Redraw only what changed** (the canvas must stay smooth at 100+ cards, and later at 60 updates a second):
- The engine hands back last time's stage / wire object when a result came out the same (`keepUnchanged`, `utils/sameShape.ts`), so "did my reading change?" is one comparison.
- Cards never read the whole graph: `useStage(id)`, `useWire(key)`, `useParams`, `useNodeName`, `useNodeChrome` and `NodePort` each select only their own piece from the store (zustand selectors; `useShallow` for small arrays). A new hook for cards must do the same — a selector over `s.nodes` / `s.edges` as a whole redraws every card on every change.
- `useFlowElements` hands React Flow last time's node / wire object when nothing about it changed (`keepSame`), and everything `SignalChain` passes to `<ReactFlow>` is stable (`useStableHandlers`, module constants): React Flow passes its node handlers on to every card, so one new function per render redraws them all.
- **Movement never goes through React.** The live loop (`hooks/useLiveMeter.ts`) calls each meter's painter 30 times a second, only while the meter is on screen (an IntersectionObserver) and not hidden (a card body zoomed out, a face zoomed in); a painter writes the moving part's own `transform` / `opacity` (one element: nothing else is styled again), and only a change (`paintStyle`, `components/meterPaint.ts`). Writing CSS variables on a meter's box instead cost ten times as much (each restyles everything in it).

Layers: `data/` (types, registry) ← `graph/` (pure queries and edits) ← `signal/` (pure maths) ← `audio/` (Web Audio: the render on real sound; its processors and the sounds made in code are pure) ← `hooks/`, `store/`, `components/`. Nothing in `graph/`, `signal/` or `audio/` imports React or the store.

### Node card shell

Every card uses `NodeWrapper` (the free-standing controls below use `FreeControl`):
- **Face-only cards** (`faceOnly`): Microphone, Instrument, Guitar Amp, Speaker, Active Speaker and Headphones show only their face — a big icon, with its buttons or knob — at every zoom, with no header or body; the name shows on hover. Their level (decision D13, replacing D11's "no level" for them): zoomed in an upright meter strip on the right of the face (`FaceMeter` in `NodeWrapper`; the face keeps `FACE_METER_ROOM` free — `reserveRight` —, the card is its registry size, 320 × 328, and 92 px wider), zoomed out the level block under the face, horizontal, as on the other cards. Where the card meets the air it reads **dB SPL** (`SPL_DB` in `signal/levels.ts`, added to its dBu: Microphone +146 — a dynamic mic sends −52 dBu at 94 dB SPL, so −60 dBu is speech at 86, singing 96, drums 110 (`AT_THE_MIC_DB`, below); Guitar Amp +116 — as loud as the Microphone in front of it hears it, 100 … 115 over its Volume (1 … 11); Speaker, Active Speaker +110 — −10 dBu plays 100, the clip level 130, a powerful PA speaker's most (the user's ask, after JBL's PRX412M); Headphones +95 — −10 dBu plays 85, the level studios mix at, 115 at most), whole dB (`formatSpl`), its bar on 50 … 130 dB SPL (`SPL_SCALE_DB` 110: the readings moved by `spl − 110`, `shift` on `MeterTrack`); the colour and the word still judge the signal in the cable (its tooltip says so — `meters.splTip`; a Microphone reads "86 dB SPL — Too quiet": its signal needs a Preamp). The Instrument reads dBu (its cable signal: an electric guitar makes next to no sound in the air). They move while the chain plays, like every meter. The Pre / Post switch (type `relay`, `overviewLevel={false}`) is face-only too, with no level: just two big PRE / POST buttons filling the card, clickable at every zoom (the name shows on hover). It is the button by an aux send that picks where the send takes its copy of the channel: PRE (`in-a`, `selectedInput: 'a'`) is its top input — wired from before the fader —, POST (`in-b`, `'b'`) the one below — from the fader's output. The send level is a Gain after it, then the Aux Bus. The Active Speaker, Headphones and the Guitar Amp keep their Volume knob beside the icon (`VolumeFace`); from Intermediate (`CHARACTER_LEVEL`) the Microphone has its Speech / Singing / Drums buttons there, stacked (`MicNode`) — not while a Guitar Amp's sound is wired into it: it hears the amp, and its own loop is not played (`plays` false). An Instrument going into a desk input without a DI Box (`stage.condition` `needsDi`) shows a dull-tone curve and a note under its icon; a speaker the hum of a DI ground loop reaches (`stage.hum`) says "You hear a hum"; a speaker or headphones fed a signal clipped on its way (`stage.distorted`) says "Bad sound — something before it distorts" in red, its meter left green (D14). A passive Speaker with no Amplifier before it is silent (`stage.condition` `needsAmp`): crossed-out icon and a note. An Active Speaker with an Amplifier before it blows (`stage.condition` `blown`): it gets speaker level (+`SPEAKER_LEVEL_DB`, at least the clip level: its meter says it clips), a cracked, smoking icon and a note replace its face. **Headphones** (Output, Beginner) are there to illustrate: they work exactly as an Active Speaker (`ActiveSpeakerNode`, `poweredSpeaker` in `PROCESS`, `amped`, `DESK_INPUTS`), blown in red. Line Input keeps a full card (it has the Mono / Stereo switch; its Music / Drums buttons are in the body).
- **Not connected** (decision D11 — no connection, no signal): a source with nothing plugged into its output (`unwiredSource`; `notConnected` in `useNodeChrome`) shows no level until it is wired: a Microphone or an Instrument says "Not connected" under its icon (every zoom); a Line Input or the Generator in a grey tag on its bottom edge (`EdgeTags`, every level) and, zoomed out, in its level's place. It does not move (the live loop skips it); the number engine and the render still work it out, so wiring it shows its level at once. The **Generator** is a full card: a Mono / Stereo switch like Line Input's, its Sound — Sine / Noise / Click (short pulses), stacked `ChoiceButtons` with a picture of each — beside a Level knob (−60 … +20 dBu, default 0); zoomed out, its icon.
- **One size per card, at every level** (2026-10-08, the user's call): the registry's `minSize` (`cardMinSize()` in `layoutHelpers.ts`; else 280 × 210) — what each card measured with the readings under it at Intermediate (Compressor / Noise Gate 618 × 366, Limiter 618 × 361, De-esser and Amplifier 412 × 361, Equalizer 410 × 361, the face-only cards 320 × 328 plus their meter's 92, Line Input 320 × 250, Generator 320 × 285, HPF 320 × 268, ADC 320 × 218, DAC 320 × 259, Master and Matrix Bus 398 × 361, Aux Bus 398 × 397). The readings went; their room went to the content: the meters take the body's height (`MeterSides` fills it), the dynamics cards' knobs are `DYNAMICS_KNOB` (56; `DYNAMICS_KNOB_BIG` 72 on the two-knob Limiter and De-esser) and their curve 188 × 160, the Equalizer's three knobs stand one above another (High on top, as on a desk), the Amplifier's Volume is a knob per channel (72), the HPF's curve is 110 tall, the Generator's buttons and knob and the Line Input's level and buttons are bigger, the converters' text too. The Graphic EQ (862 × 471) and the Parametric Equalizer (682 × 466) got shorter instead; the DI Box (432 × 309) and the Pre / Post switch never had readings. No shape rule (the 4:3 landscape rule went with the moving meters — D10).
- **Meters at the sides** (`MeterSides`): a card with In / Out meters shows them as upright strips (`MeterStrip`, see Meters) — what arrives on the left, what leaves on the right, like a DAW plug-in — taking the body's whole height (`MeterSides` fills the body): Compressor and Noise Gate (knobs \| curve between them, `twoColumns`), Limiter, De-esser, Amplifier, Intermediate Equalizer, Parametric Equalizer (its curve and its bands as a table of knobs — Gain, Freq on a log scale, Width — between the meters), Graphic EQ (its sliders), DI Box (In only), the buses (Out only) — their sizes under *One size per card*. Mono and stereo are the same height, and so is Bulgarian (the cards' fixed sizes hold it), except the DI Box: 70 px taller (its description).
- **Width follows content** above that minimum, text wraps to fit.
- A fixed **56px header** (icon, title, On/Off) keeps the first port line at `PORT_TOP` (80px — just below the header's divider, clear of the header buttons) on every card, so wires between cards stay straight; stacked ports are `PORT_GAP` (36px) apart. Port rings are 28px (40px while showing the unplug ×) so they are easy to see and hit.
- The header row is **icon · title · On/Off (bypass)**; Help and Remove are in the right-click menu. Types with `bypass: false` in the registry (sources, outputs, faders, switches, `master-bus` …) have no On/Off — the control itself is the state. Every node, including Master Bus, can be removed.
- **A card never changes size while values change** (no flicker). Wrap every changing reading in `StableText` (`components/controls/StableText.tsx`), which reserves the width of the widest value it can show: `LEVEL_SAMPLE` for signal levels, `widestFormat()` for a control's readout (both in `utils/readout.ts`). `KnobControl`, `VerticalFader`, `ControlSlider` and the meters (`MeterStrip`, `MeterBar`) already do this. Text that only sometimes shows keeps its space (`visibility: hidden`) instead of being removed. The "Bypassed" tag sits on the header's bottom line, outside the layout. Wide cards (Parametric EQ) use a fixed body width.
- Controls and In/Out meters stay on the cards; there is **no status chip**.
- Only types with `stereo: 'optional'` (Line In, Generator, Aux Bus) get a **Mono | Stereo** switch under the header (not dimmed by bypass). Meters take `r` (the right side) to show L / R bars.
- A thin **chain-colour stripe** on the card's top edge shows which sources (chains) pass through it.
- **Overview** (`overview` in the store, zoomed out): the header, Mono / Stereo switch and body stay mounted with `visibility: hidden`, so the card keeps **exactly** the same size and its ports stay put; `OverviewFace` is drawn over them (`inset: 0`, `pointer-events: none`, under the port rings). It shows the header's label (dynamic names included) fitted by `fitText` (weight 600, up to 96px — HPF up to 70px, capitals look bigger: `nameMax` in `NODE_LOOK` — a second line only if that makes it bigger), or the card's `overviewArt` instead (sources and speakers: their icon, `OverviewIcon`), and at the bottom the level **leaving** the card (louder of L / R) — on a face-only card too (D13), in dB SPL where it meets the air: a meter (a stereo signal: two, L above R, each in its own side's health colour and moving with its side), the reading (`formatDb`) and the health word in `--signal-*-text` (darker shades in the light theme, ≥ 4.5:1). Sizes follow the card width; the health word has one size per language (the longest word fits), so a health change never moves anything. Bypassed: the face at 50% with the "Bypassed" tag. Crossfade 120ms (`.lsc-fade`), none under `prefers-reduced-motion`.

### Free-standing controls

**Gain (Preamp), Pan (Balance), Fader (Main Fader), Switch and Pad are not cards**: each is the bare control with its connection points (`FreeControl`) — a 110px knob, a 440px fader (`VerticalFader scale={2.4}`, −100…+10 dB on a desk-style uneven scale: `utils/faderTaper.ts`) with a solid desk-style cap (`FaderCap`: black, red on the Main Fader; its white line marks the value) and a desk-style print: numbers on the left, a tick each side of the track (the cap slides over them), a dotted high-resolution zone around unity (+5…−5 dB, one dot row per 0.5 dB, in two columns beside the cap so it is never hidden) and half-way ticks below (`FADER_MARKS`), a 110px square On / Off button with rounded corners (`SquareButton`: the Switch's ON / OFF lit green, the Pad's −20 dB / OFF lit in the hot colour, one fitted size for both of its words). Large, and the same at every zoom (no overview face). Under the control: its name (follows the wiring, wraps at 200px) and its reading (`StableText`). The Switch (palette: On Off Switch) shows no name (`showName={false}`): its On / Off button says it all, the name shows on hover; the Pad shows its name (PAD) under its button (one of the buttons since D11: no card, no level, no readings). Pan has a direction indicator under it — a dot on a short track between L and R, following the knob, not the sound (D11; its tooltip says where you will hear it, or for Balance which side leads) —; the Main Fader has no meters (its cap is red; the cards around it show the mix). The Gain shows its setting only. The control sits so that its port line is at `PORT_TOP`, level with the cards' first port, so wires stay straight. Grab the name or the space around the control to move it; the control itself carries `nodrag nopan`. Only the left button moves a knob or fader (a right-click opens the menu and changes nothing); grabbing the fader cap drags it from where it is held, a click on the track jumps there. Their drop-preview sizes are the registry's `freeSize`.

### Mono / Stereo

**One wire carries a whole stereo signal.** Cards have one input and one output; only a bus splits its mix into separate **L and R outputs** (one per speaker). Registry field `stereo: 'never' | 'follow' | 'optional' | 'always'`:
- **follow** (every processor, incl. gain, hpf, pad, relay, di-box, adc / dac, pan): no switch — passes on what it gets. A stereo wire in → a stereo wire out; the Relay follows its selected input.
- **optional** (switch, `params.stereo`): **Line In** (Stereo = a stereo file's left and right on one wire; a mono file the same on both sides — the number engine puts both at the knob's level, the render measures each side), the **Generator** (Stereo = the same sound on both sides) and **Aux Bus** (Stereo = `out-l` / `out-r` outputs from `stereoOutputs`). `setNodeStereo` only moves the Aux outputs: `out` ↔ `out-l` (+ `out-r` back to `out`). Inputs never change.
- **always**: Master Bus and Matrix Bus — one input (any number of wires), outputs `out-l` / `out-r`.
- **never** (one channel): mic, instrument, guitar-amp, speakers. A stereo wire arriving here is folded (L + R, about +6 dB when both sides match).
- **What a wire carries** (`WireSignal` in `signal/engine.ts`: `kind` + `l` / `r`, each side's peak, average, noise and hum — `SideLevels`; the kind is read from the wiring, `outputKind()` in `graph/queries.ts`): `mono`, `stereo`, or `left` / `right` — one side of a mix, from a bus's L / R output. A side wire **keeps its side through effects** (Aux L → Comp → Master lands on the left only). A stereo bus adds every wire's `l` to Left and `r` to Right: a mono wire lands on both sides at full level (that is why Pan is needed), a side wire on its side.
- **Pan**: always sends a stereo wire. Mono / side wire in = Pan knob (equal-power, −3 dB each side at centre); stereo wire in = Balance knob (centre = unity). Label and help follow (`stage.role` `balance`).
- **Maths**: the engine writes `wires` (what each output carries; colours use its louder side, `levelOf`). Stereo nodes run `processSide` once per side; a stage's `in` / `out` are then stereo signals. Comp, limiter, de-esser and gate run **linked** in stereo: the louder side sets the gain change, both sides get it.
- A stereo wire is drawn as a **twin line** (also the live preview from a stereo output); an output carrying one side shows an **L / R letter**.
- **Main Fader** (`utils/mainFader.ts`): wiring a Fader to a stereo bus's L or R output turns that wire into the **Mix** wire (`mix` port, the whole stereo mix), the Fader gets **L / R outputs** and every wire on the bus's L / R moves onto it (dropping a Fader onto a bus's L / R wire does the same). Effects may sit between the Mix output and the fader. A Fader fed only one side (effects after an L / R output) is a plain fader. Unplugging or deleting the Main Fader hands L / R back to the bus (other Mix wires fall back to L); deleting the bus leaves a plain fader. Extra wires from the Mix output are the **pre-fader** point (PFL is built by the user from switches, wires and buses). Port layout is read from the wires, never stored.
- **Graphic EQ, Amplifier and Limiter take L / R over the same way** (registry `splits`: graphic-eq, amp `true`; fader, limiter `'mix'` — `splitsOnlyMix`: only from a bus's mix, so a stereo channel through a Limiter stays one wire): wired to the L or R of the card holding them (a stereo bus, its Main Fader, another EQ / amp / limiter), that wire becomes the holder's **Mix** output (one stereo wire) and the holder's L / R wires move onto them — the chain carries one stereo wire up to the last of them, which shows **L / R** (bus → Main Fader → Graphic EQ → Amplifier → two speakers; bus → Limiter → Main Fader). `attachMainFaders` takes over, tidies, and again until the tidy changes nothing (a Limiter dropped between a bus and its Main Fader starts splitting, then the fader takes it over); a restored autosave is settled the same way (`getInitialCanvas`). The Matrix send stays on the Main Fader. Fed any stereo wire (`outputKind()` reads what an output carries from the wires) they split it into L / R; fed one channel they stay single-channel; with nothing plugged in they keep the layout their wires show, so re-plugging restores L / R (`splitsStereo()`). A stereo Amplifier is a two-channel amp: channel A takes the left side (`gainDb`), channel B the right (`gainDbR`), each with its own Volume; the Graphic EQ's sliders shape both sides alike.
- **Matrix send** (same method): wiring a stereo bus's (or its Main Fader's) L or R output to a Matrix Bus turns that wire into the **Matrix send** (`send` port below R, one stereo wire, "L+R"). It is post-fader: a Main Fader takes the bus's send with its L / R, and the pre-fader Mix output cannot feed a matrix. A mono Aux Bus feeds a matrix from its `out` or from the Fader after it (effects may sit between) — a mono wire, landing on both sides. The send never follows L / R onto a Graphic EQ or Amplifier, and one that fed a matrix while its chain was mono hands it back to the bus (or its Main Fader) when it takes L / R over — only a bus or its Main Fader holds a send.

### Level system

The active complexity level is stored as `complexityLevel` in `signalStore.ts`, persisted to `localStorage`. Its type `ComplexityLevel` (`'beginner' | 'intermediate' | 'advanced'`) and `LEVELS` live in `src/data/levels.ts`.

Levels control **palette visibility only** — they do not auto-populate the graph:

| Level | Visible palette items |
|---|---|
| Beginner | mic, line-in, instrument, di-box, active-speaker, headphones, gain, fader |
| Intermediate | + guitar-amp, generator, hpf, eq, comp, pad, noise-gate, limiter, deesser, switch, relay (Pre / Post switch), pan (Pan / Balance), master-bus, aux-bus |
| Advanced | + speaker, amp, graphic-eq, adc, dac, matrix-bus |

Each type's `minLevel` in `NODE_REGISTRY` is the source of truth for this table (a type shows from its level up). A level can also change a card's layout, name and starting params: the EQ (`EQNode`) is the **Equalizer** in Intermediate — three knobs (Low / Mid / High, no curve), Low and High fixed as shelves (`initialParams()` in `nodeRegistry.ts`) — and the **Parametric Equalizer** in Advanced, with a draggable curve and a Bell / Shelf switch on Low and High. Level-dependent names live in the locales' `levelNames`; `useTranslation` applies them to `palette.items` and `nodes.<type>.label`. Switching level clears the canvas (with confirmation); no level pre-places anything.

### Signal health zones

| Zone | dB range | Color | Meaning |
|---|---|---|---|
| `too-quiet` | < −40 dBu | Blue | Noise floor risk |
| `good` | −40 to 0 dBu (unity) | Green | Target range |
| `hot` | above unity, below +20 dBu | Yellow | Less headroom left |
| `clipping` | **peaks** ≥ +20 dBu (clip level — where every gain stops) | Red | Distortion |

The first three zones come from the average; **clipping comes from the peaks** (decision D4, at every level — Beginner too, D5; the engine takes no level): a voice (peaks 12 dB above its average) turns red at an average of +8 dBu. `getHealth(db, domain, peakDb)` (the peak left out = the average); `healthOf(wire, domain)` judges a whole signal. A stage's `health`, the wires, port rings, the meters' health words, Peak numbers and red clip lines (each L / R bar of a stereo meter on its own side's peaks) and the overview face (`outHealth`) all judge it this way: the loop's verdict, not the moment's. The meter bars themselves are coloured along their scale, not by the verdict (D16, below).

**Meters** (`SignalMeter.tsx`), as a DAW draws them (D16, after Sound Forge's) — three readings in one bar per side, the upright strips on the cards and the horizontal bars of the overview faces drawn alike (`MeterTrack`): the solid bar is the average (RMS). **The colours belong to the scale** (`meterZones` in `signal/levels.ts`): a zones layer painted once — blue where a level is too quiet (below unity − 40), green good, yellow hot, red the top 2 dB under the ceiling (`CLIP_ZONE_DB`) — with two covers in the track's colour sliding over it (`.lsc-meter-pale` down to the average, `.lsc-meter-dark` down to the peaks: `paintBar`); a dB SPL meter's zones are moved with its readings, so they still judge the signal in the cable. **The scale** runs evenly over 80 dB up to the ceiling, then the bottom 10 % (`METER_TAIL`) squeezes everything quieter down to silence: the bar's bottom is −∞ (`dbToPercent`). **Its numbers** (`scaleMarks`): beside a card's bar — between L and R in stereo, left of it in mono (`MeterScale`, 22 px, 9 px numbers; as many as the bar's height has room for — `fitScaleMarks`, measured with `useHeight`, a short bar drops −60 first) — every 10 dB then −∞: +20 … −60 dBu (unity 0 bold, +20 red), 0 … −80 dBFS on a digital meter (−18, unity, in place of −20), 130 … 50 on a dB SPL meter; under an overview bar only three, smaller (`MeterScaleRow`, 0.75 of the unit): −∞ 0 +20, −∞ −18 0, −∞ 110 130. **A red line across the top** (the right end lying), twice as thick as the peak mark, lights up while that side's peaks reach the clip level (`clipping`: the loop's verdict, at every level — D5). From Intermediate (`useReadingsShown`) a thin line in `--lsc-fg` (white on dark, dark on light) shows the peaks, and a grey fog (`--lsc-noise-fog`) from the quiet end the noise once it reaches the even part of the scale (above −60 dBu, −80 dBFS; not in the tail). Beginner sees the bar alone (with its numbers and the clip line). A card's meter (`MeterStrip`, `STRIP_W` 76 px in every language — the scale fits in it: no card changed size): its name, the bar (32 px thick; two, L and R, 22 px each, each with its letter, in stereo — doubled on 2026-10-06, the user's call), its numbers and the health word (11 px bold, wrapping; it keeps the height of the tallest), the same height mono or stereo. The numbers (D15): from Intermediate a **Peak** line (the peak hold — the mark —, in the health colour) and an **RMS** line (the solid bar), each a name and a value on one line, a stereo signal's louder side, then the unit; at Beginner (D3) the loop's average — mono: the number and its unit, stereo: an L and an R line. A horizontal bar (`MeterBar`) remains on the overview faces — as thick as their number is tall, an L and an R bar for a stereo card (0.7 of that each), a face-only card's zoomed out too (D13); under it its three scale numbers, then a Peak row (the health word beside it, or under when it does not fit) and an RMS row from Intermediate, one unnamed number (the average) at Beginner. The level block takes at most half the face (`LEVEL_SHARE`): on a small card the numbers shrink (not below `NUMBER_MIN`) so its name or icon keeps its room. Pan's L / R rows went in 11b (its direction indicator instead). A meter's `title` explains it (`meters.tip`, Beginner `meters.tipBeginner`).

**Moving meters** (decision D10): from Intermediate, once a source is wired, every meter plays the sound as a DAW's meter does (`audio/meters.ts`, played back by `hooks/useLiveMeter.ts`): the solid bar is the RMS over the last 300 ms, the pale part above it the peak (the loudest sample at once, falling back 20 dB in 1.7 s — IEC 60268-18), the thin line the peak hold (3 s, then falling like the peak); the fog stays (the noise is measured with the music stopped). A dynamics card's turning-down bar, its curve's Peaks and Average marks and its Open / Limiting word move too. Nothing moves on Pan, the Gain or the buttons — they have no meter (D11), nor does the Main Fader. The health words and colours stay the render's — the loop's — so nothing flickers (the user kept that in D11); the Peak and RMS numbers move with their meter (D15: `LiveLevel` in `SignalMeter.tsx` — the still reading drawn by React, the moving one written over it by its painter with `paintText`, at most every `TEXT_EVERY_MS` (500 ms: twice a second — the user's call, 2026-10-06; 8 times a second, a DAW's pace, was too fast to teach with)). There is no Play / Pause: the loop just repeats, once a source is wired (no connection, no signal — D11). Beginner: still (D3) — the bar the loop's average, the mark its loudest peak (the still picture is what React draws; the painters only write over it). Reduced motion does not stop them (D12).

Digital levels (dBFS, after an ADC) use the same zones moved down by the converter alignment (`ALIGNMENT_DB` = 18: 0 dBu ↔ −18 dBFS): good up to −18 dBFS, clipping when the peaks reach 0 dBFS, the digital ceiling (`ceilingOf(domain)`) — where a Gain stops, too. A meter's bar ends at its domain's ceiling (`dbToPercent`): −60 … +20 dBu analog, −80 … 0 dBFS digital (then the tail down to −∞), so a bar reaching the top clips either way (a digital bar used to run to "+20 dBFS" and clip three quarters up); unity sits 2.25 % higher on a digital bar, and its scale reads dBFS. The ADC / DAC cards print their out level in its health colour. Meters, port rings, wires and the overview face pass the stage's domain (`stage.domain`, and `stage.inDomain` for what arrives — `useStereoLevels` gives `inDomain` / `outDomain`); `formatDb(db, domain)` prints dBu or dBFS.

### Signal math (simplified for education)

This is the number engine: the instant picture, and the step a change moves the readings by until the next render on real sound arrives (see *Real sound* below — the cards show the render's). Every side of every wire carries four readings (`SideLevels`): **peak** (the loudest moments), **rms** (the average — what the meters and every formula below show), **noise** (what you hear when the music stops: hiss and hum together) and **hum** (the hum part of the noise, kept apart for its glow). Signal-to-noise = average − noise (`snrOf`); headroom = ceiling − peak (`headroomOf`).

- **Sources** (`soundOf`: peaks by what it plays — `PEAKS_ABOVE` —, noise by source — `NOISE_BELOW`): Microphone — a voice, speaking or singing, peaks 12 dB above the average, noise (the room and its own hiss) 66 dB below (−48 / −60 / −126 dBu); what it picks up reaches it louder or softer (`AT_THE_MIC_DB`, `loudnessOf` — the number engine and the render): speech at its usual level, singing +10 dB (−50 dBu, 96 dB SPL), drums +24 (−36 dBu, 110 dB SPL — the default Preamp's +40 then clips their peaks: they need less gain), the room and its hiss staying at −126 (so 66 / 76 / 90 dB below the signal); Line Input — music, peaks +12, noise −80 dB; Instrument — a guitar, peaks +15 (plucks), noise −70 dB. What a Microphone picks up — Speech, Singing or Drums — and a Line Input plays — Music or Drums — is its `character` (decision D8; the buttons show from Intermediate — D3 —, Speech / Music below); Drums: peaks +18 (on a Line Input the same average and noise; on a Microphone louder, above). **Generator** (`sound`, `levelDb`, Intermediate): Sine +3, Noise +12, Click +18 (short pulses); its noise −90 dB. At +10 dBu a sine is hot (peaks +13), clicks clip (+28, flattened at +20). A Mic in front of a Guitar Amp hears the amp's readings shifted to mic level, plus its own room noise (the amp decides the peaks, whatever its switch says).
- **Hiss**: every powered card adds its own to the noise that arrives, **before** it does its job (`processSide`): −80 dBu (`HISS_DBU`), a Preamp −128 dBu (`PREAMP_HISS_DBU`). So a make-up gain lifts the hiss of the cards before it, and a gate can shut its own hiss off. No hiss: `PASSIVE` cards (DI Box, Pad, Switch, Pre / Post switch, Pan, passive Speaker; sources bring their own noise), stages working digitally, a bypassed card, a card with nothing plugged in. ADC / DAC hiss on their analog side.
- **Gains, faders, EQ, HPF, Pad, Amp, Pan / Balance, send knobs, ADC / DAC**: all readings move by the same dB (`shifted`).
- **Peaks** are flattened at the ceiling after every card (`flattenPeaks`: +20 dBu analog, 0 dBFS digital, never below the average): the gap shrinks — the distortion — and turning down later does not bring it back.
- **Dynamics** (compressor, limiter, gate, de-esser): every reading goes through the card's curve on its own (`throughCurve`); `gainReductionDb` is the curve's on the average. A guess for the moment before the render (decision D9): no real compressor can treat the peaks apart from the average — it gives one gain to the whole moment, over its Attack and Release (see *Real sound*). A compressor brings the average down and costs as much signal-to-noise (the noise sits under the threshold and only gets the makeup gain); a limiter caps the peaks; a gate set between the noise and the signal drops the noise by its Range; a de-esser leaves the signal as a whole alone (only its sibilance comes down).
- **Adding signals** (buses, a stereo wire folded into one channel — `sumSides`): peaks and averages as voltages (+6 dB for two equal ones), noise and hum as powers (+3 dB per doubling).
- **Where it ends**: Mic → Preamp +50 → EQ → Gain → Fader → Master Bus → speaker ends at −10 dBu, 60.4 dB above its noise, peaks at +2 (18 dB headroom). The same with the Preamp 30 dB too low (+20) made up later (Gain +20, Fader +10): the same level and peaks, 37.0 dB — the EQ's hiss landed on a voice 30 dB too weak. Beginner's default Mic → Preamp (+40) → Fader → speaker: 56 dB. On real sound the same: 62 / 38 / 56 (whole dB, the help texts' numbers); with the default Compressor in the well-set strip, 53 — its real gain reduction (6.8 dB on speech) costs that much.

- **Gain**: the first Gain after a Mic or a DI Box's XLR Out (effects such as a Pad may sit in between, `preampSourceOf()`) is its **Preamp**: `clamp(input + preampDb, +20)`, 0…+60 dB. Anywhere else it is a plain gain stage: `clamp(input + gainDb, +20)`, −∞…+20 dB (fully left = off); after an ADC it stops at 0 dBFS (`ceilingOf(domain)`). Each mode keeps its own param; the card title, knob and help follow the wiring (`stage.role` `preamp`).
- **DI Box**: XLR Out (`out`) = `input − DI_DROP_DB` (20 dB: mic level, for a Preamp); Direct Out (`direct`) = input, unchanged (instrument level, for a guitar amp). Bypassed: both = input, no conversion. Ground Lift off, Direct Out reaching a Guitar Amp and XLR Out wired = a ground loop: a hum starts on the XLR Out at `HUM_DBU` (−80 dBu), joins the noise and rides to the end of the chain (`stage.hum`, its level leaving each card; `hums` per output). It **follows the signal** like all noise (decision D1): a Preamp's +40 lifts it to −40 dBu, a fader at −10 takes it to −50 — the gap to the music stays —, a gate closed in the pauses shuts it off, an ADC / DAC moves it to the other scale. Only Ground Lift on clears it. The DI card shows "Hum!" in place of its description and lights up the Ground Lift button
- **Instrument**: `levelDb` (−30). Reaching a desk input (`DESK_INPUTS`) without a DI's XLR Out — straight, through pedals or a DI's Direct Out — sets `condition: 'needsDi'` (levels unchanged: the lost high notes are told, not measured)
- **Guitar Amp** (Intermediate): plays `input + guitarAmpGainDb(volume)` — its Volume goes to 11 (`GUITAR_AMP_MAX`, the user's wink of 2026-10-06; `volume` 0 … 11, step 0.5): 0 silent, 1 +14 dB (a guitar at −30 dBu: 100 dB SPL), 1.5 dB a step, 11 +29 (115 dB SPL); its default 5: +20 (106). Takes only a guitar at instrument level; its `sound` output (dotted wire) goes only into a Mic, which then sends `sensitivityDb + amp − GUITAR_REF_DB` (−40 dBu with the amp at 5), silent when the amp is. An older file's `volumeDb` on a Guitar Amp is left unused (it opens at 5). A Mic with nothing plugged in sends `sensitivityDb`
- **Amp**: `output = input + gainDb`, Volume −∞…0 dB (only turns down — line level is already loud enough; fully left = off). Stereo: two channels, A (the left side, `gainDb`) and B (the right, `gainDbR`, `processSide` gets the side), each its own Volume; B follows A until one of them is turned in stereo (A's first turn writes B where it was)
- **ADC / DAC**: `dBFS = dBu − alignmentDb` and back (default 18: unity 0 dBu = −18 dBFS)
- **HPF**: the level change of pink noise through a 2nd-order high-pass at the cutoff (`hpfLevelChange` in `signal/eqMath.ts`: −1.0 dB at the default 80 Hz; on the speaking voice, really, −0.4)
- **EQ**: the level change of pink noise through the bands added together (`eqLevelChange`: Low +3, Mid −2, High +2 ≈ +1.2 dB; on the speaking voice, really, +1.5)
- **Graphic EQ**: 31 one-third-octave bands, 20 Hz … 20 kHz (`GEQ_CENTERS` in `signal/eqMath.ts`, params `b0`…`b30`, ±12 dB in 0.5 dB steps); the level change is the pink-noise-weighted sum of the band bells (Q ≈ 4.3). The card is the Parametric EQ's size: In | Out meters, a readout of the band being touched, a Flat button, and the 31 sliders with a curve through their caps (double-click = 0 dB; a drag stays on the slider it started on) In stereo the sliders split into two half-height banks in the same space — L on top (`b0`…`b30`), R below (`r0`…`r30`); untouched, R copies L, and the first touch on R writes all its bands (independent from then on). Flat resets both.
- **Compressor**: `gainReduction = max(0, (input − threshold) × (1 − 1/ratio))`, then `output = input − gainReduction + makeupGain`. On real sound (`audio/processors.ts`) the reduction moves toward that, at the level of the moment (heard over 3 ms), over Attack (`attackMs`, turning down) and Release (`releaseMs`, letting go): a speaking voice at −10 dBu through the default 2:1 at −20 comes down 6.8 dB on average, its peaks 12 dB above the average in, 17 out with Attack 10 ms (the start of each word gets through), 16 with 1 ms; a singing voice, whose notes start softly: 12 in, 10 out at 1 ms; drums 18 → 22. The noise, under the threshold, only gets the makeup gain — signal-to-noise drops by the gain reduction
- **Noise Gate**: open (`input ≥ threshold`) → `output = input`; closed → `output = input + range` (Range −80…0 dB, −80 ≈ silence). On real sound it opens while the peaks of the moment reach the threshold, stays open for Hold (`holdMs`), opens over Attack (`attackMs`) and closes over Release (`releaseMs`), and starts closed: a threshold between the noise and the music drops only the noise (the pauses: the Hiss reading of a voice through the default gate, 142 dB below); above the average it opens only on the peaks and cuts the rest of the music. Its own hiss (−80 dBu) is part of what it hears, so a threshold under it never closes on the noise. Same card layout and size as the Compressor
- **Limiter**: on real sound no sample passes its ceiling, and each caught peak turns that moment down (letting go over 50 ms), so the average drops too — a voice at −10 dBu with peaks at +2 into the default −3 dBu ceiling: 3.5 dB
- **De-esser**: on real sound it splits the signal at its Frequency (a 2nd-order low-pass; the rest is the sibilance) and turns only the rest down, 8:1 over its threshold, quickly (1 / 50 ms): a speaking voice at −10 dBu, the default −20 dB threshold: the "s" sounds down 5.7 dB (the readout), the voice as a whole 0.07; a singing voice, with hardly any "s": nothing
- **Fader**: `output = input + faderDb`, −100…+10 dB. The fader's travel is uneven like a desk's (`faderTaper.ts`): unity at 85% of the travel, 0.5 dB steps above −20 dB, the quiet end squeezed together
- **Switch**: `output = on ? input : −∞`
- **Pre / Post switch** (`relay`): `output = selected input` (PRE = top, POST = lower); the other input is cut off
- **Master Bus / Aux Bus**: `output = 20 × log10(Σ 10^(inputN/20))` (voltage sum of all wires — two identical signals give +6 dB), per side in stereo; the noise `10 × log10(Σ 10^(noiseN/10))` (+3 dB per doubling), then the bus's own hiss
- **Matrix Bus** (always stereo): a bus of buses — only finished mixes go in, after their fader (a stereo bus's Matrix send, a mono Aux's output). Each wire first gets its bus's send knob (`params[send-<busId>]`, one per bus; audio taper `taperToDb`: 0 = off, 75 = 0 dB), then the usual stereo bus sum (a mono bus lands on both sides at full level). Its overall level is a Fader after it (its Main Fader)
- **Pan**: equal-power, `L = in + 20·log10(cos(p·π/2))`, `R = in + 20·log10(sin(p·π/2))`. **Balance**: fades only the opposite side, linearly, centre = unity

The number engine is intentionally simplified: it teaches the idea at once, without filter maths.

### Real sound (decision D9)

**The movement** (D10): the music render also records, slice by slice (10 ms), each tap's loudest sample and power, from a slice boundary of the loop; `measureChain` turns them round to the loop's start and works out how a DAW's meters would move over them (`audio/meters.ts`). Every sound in a chain is one loop long, so after the dynamics settle the chain repeats exactly every `LOOP_S`: that one loop is everything it plays, and the meters play it back in time with the clock instead of a live AudioContext (no click needed to start, no audio thread running, the same render the readings come from). Checked: the moving RMS averages (as power) to the still reading exactly, its loudest peak is the still peak, and two renders of different chains give the same card the same frames (0 dB apart). Speech at −10 dBu: the peak 7 / 10 / 18 dB above the RMS (10 / 50 / 90 % of the time); clicks over 14; a sine 3.

The cards show what a render of the chain on real sound measures (`store/measuring.ts` → `audio/measure.ts`): the same plan built as Web Audio nodes (`audio/chainAudio.ts`) in an OfflineAudioContext — silent, off the main thread, faster than real time — playing the sources' loops (`audio/loops.ts`; made by `scripts/make-loops.py`, D7) or the Generator's sounds (`audio/sounds.ts`), every powered card adding its own white hiss, the dynamics our processors in an AudioWorklet (`audio/processors.ts`), whatever would pass the clip level cut off. Two renders: the music (peaks, average over a loop, once the dynamics have settled) and the quiet (the music stopped: the noise, and a ground loop's hum — one Fourier bin at 50 Hz). Between a change and the render's readings the number engine moves the last ones by its own step (`withMeasured`): a fader or a gain is exact at once, a filter or a dynamics card close. Where real sound differs from the number engine, it is real: an 80 Hz HPF takes 0.4 dB off a speaking voice (pink noise: 1.0) and ~9 dB off a 50 Hz hum; a boosted high shelf lifts the hiss (white) more than the voice; different sounds on one bus add up to less than the voltage sum (8 channels of the stress chain: 2.3 dB less), the same loop twice to exactly +6 dB; clicks clipped at +10 dBu lose 4 dB of average; a compressor's peaks depend on its Attack and the sound (above). Linear chains read as the number engine to ~0.05 dB (the loops' peaks within 0.15 dB of `PEAKS_ABOVE`). The loops (all 10 s, one piece of music): Microphone Speech / Singing / Drums, Line Input Music / Drums, Instrument and Guitar Amp a guitar (decision D8).

### Design decisions

Made with the user (the code cites them by number):
- **D1 — A hum follows the signal**, like all noise: a fader turns the hum down with the music and the gap stays. Only fixing the cause (Ground Lift) removes it.
- **D3 — Beginner shows nothing new**: the meters' peaks and noise, their Peak / RMS numbers, the sources' sound buttons and the moving meters start at Intermediate (`DETAIL_LEVEL`, `CHARACTER_LEVEL`); at Beginner a Microphone plays Speech, a Line Input Music.
- **D4 — Clipping is judged on the peaks**: a card is red as soon as its peaks reach the clip level, whatever its average (since D16 the bar's colours belong to its scale; the red clip line says it). **D5** — at every level, Beginner too; the engine takes no level.
- **D7 — Real audio** (Web Audio) instead of homemade simulations: the chain is played on short loops made for the app (no recordings of real people, no copyrighted music); the dynamics are our own processors in an AudioWorklet.
- **D8 — The loops on the sources**: Microphone Speech · Singing · Drums, Line Input Music · Drums, Instrument and Guitar Amp a guitar. Older files' `melodic` opens as Speech / Music, `percussive` as Drums.
- **D9 — Every card's readings come from the render** on real sound; the number engine is the instant picture, moving the last render's readings by its step until the next one.
- **D10 — The meters replay the render**, not a live AudioContext: every sound is one loop long, so the render records the loop slice by slice and the meters play it back on the clock. No Play / Pause; DAW meter maths (RMS 300 ms, peak and hold, the noise floor as the fog); meters upright at the cards' sides (In left, Out right), the 4:3 rule gone; nothing moves at Beginner (D3). Nothing more on the wires than the flow animation that shows the direction (steps 12 and 13 of the plan were dropped).
- **D11 — Meters only where a meter belongs**: face-only cards show their icon, buttons or knob and notes, no level (since D13 they have one); Pan a dot on an L–R track; the Pad a bare button; zoomed out the other cards keep their meter; a source with nothing wired shows "Not connected" — no connection, no signal. The numbers, health words and colours stay the whole loop's while the meters move.
- **D12 — Reduced motion does not stop the meters** (2026-10-06): with it they stood still on the user's computer, in every mode. Nor the wires' flow animation (`.signal-line-animated`), which shows the direction.
- **D13 — Sources and speakers have a level meter** (2026-10-06, the user's call, replacing D11 for the face-only cards): Microphone, Instrument, Guitar Amp, Speaker, Active Speaker, Headphones — upright beside the face zoomed in, horizontal under it zoomed out; dB SPL where sound meets the air (a Microphone by what it picks up, speakers up to 130, the Guitar Amp 100 … 115 — it goes to 11), the Instrument in dBu.
- **D15 — A meter's numbers are its Peak and its RMS, and they move** (2026-10-06, the user's call, replacing D11's still numbers): from Intermediate, under every meter, "Peak" (the peak hold, the mark's value) and "RMS" (the solid bar's, the last 0.3 s), moving with the sound, changing twice a second (same day: 8 times a second was too fast for learners); the colours and the health word stay the loop's. Beginner keeps one number, the average (D3). The bars are twice as thick as before, in today's style.
- **D14 — A clip is heard at the end, however green the meters after it** (2026-10-06): a speaker or headphones fed a signal clipped anywhere before it says "Bad sound"; the colours along the chain stay as they are — clipping can't be seen where it doesn't happen, but it is always heard.
- **D16 — Meters in Sound Forge's style** (2026-10-08, the user's choices from animated mock-ups, after Sound Forge Pro's "PPM + VU-14" meter): one bar per side as before (solid RMS, pale peaks, a thin hold line — not Sound Forge's separate peak and VU bars); its colours belong to the scale, at the health edges (blue below unity − 40, green to unity, yellow above, red in the top 2 dB); an even scale down to −60 dBu / −80 dBFS, then a squeezed tail to −∞; dB numbers beside the bars (between L and R), dBFS on a digital meter; Peak and RMS numbers stay under the bars (D15); a red line across the top, twice as thick as the hold line, lit while it clips; the horizontal overview bars look and scale the same, with only −∞ 0 +20 (dBFS −∞ −18 0) under them.

(D2 and D6 were replaced by D8 and D9.)

### React Flow notes

- `nodeTypes` is `NODE_COMPONENTS` (`components/nodes/index.ts`), defined **outside** any component to avoid re-registration on every render. Components read their type from React Flow's `type` prop.
- All interactive elements inside nodes (sliders, buttons) carry `nodrag nopan` CSS classes so the canvas does not intercept their pointer events.
- Edges are colored from health values computed by the engine (`useFlowElements`), not stored in React Flow state.
- Every prop of `<ReactFlow>` is stable between renders (see *Redraw only what changed*): no inline arrow functions, arrays or objects — wrap handlers in `useStableHandlers`, hoist constants.
- **`nodeOrigin` is `[0, 0]`**: a node's `position` is its top-left corner. All layout helpers assume this.
- Anything that must escape React Flow's transformed viewport (e.g. `ConfirmDialog`) uses `createPortal` to `document.body` — the viewport's CSS `transform` breaks `position: fixed` inside its DOM tree. Canvas overlays that must not start a wire or a waypoint (the help popover) carry the `lsc-overlay` class.
- `nodesDraggable`, `elementsSelectable` and `panOnDrag` follow `toolMode`. `nodesConnectable` is always `false` — connections are handled entirely by the custom click system (`useWireDrawing`: capture-phase `mousedown` on `document`), not React Flow's drag mechanism.
- Wiring acts on `mousedown`, so the `click` that follows a wiring press on a port is swallowed (capture-phase `click` listener, `useSwallowClick`). Otherwise it lands on the input that was just plugged in — by then a connected input, whose click unplugs it — and the new wire vanishes. A plain unplug click (no wire being drawn) is never swallowed.
- **`Node` name collision**: ReactFlow exports `Node`; the DOM also has `Node`. Import ReactFlow's as `type Node as FlowNode` to avoid conflicts.
- `MasterBusNode` serves `master-bus`, `aux-bus` and `matrix-bus` (reads its type from `type`; the Matrix Bus adds one send-knob row per bus). Its one input (`in`) comes from the registry and accepts many wires.
- While `highlightEdgeIds` is not empty, `useFlowElements` gives nodes outside those wires' chains the `lsc-dimmed` class and fades their edges.
- **Handle hit-testing**: custom `<Handle>`s default to `isConnectable`, so React Flow gives them the `connectionindicator` class and `pointer-events: all` even in Select mode — that is what lets the mouse-follow switch find them with `document.elementsFromPoint`. `.lsc-connect-mode` (on the canvas wrapper) also forces it. Handle type (source vs target) is detected via `classList.contains('source'/'target')` — there is no `data-handletype` attribute.
- **Display nodes carry `measured`.** They are rebuilt from the store on every change (then swapped back for last time's object where nothing changed, `keepSame`); a node without `measured` is new to React Flow, which hides it (`visibility: hidden`) until re-measured on the next frame — a click in that gap lands on the pane (a knob drag used to pan the canvas). `useFlowElements` keeps React Flow's sizes from `onNodesChange` (`dimensions`, `keepSizes`) and hands them back, except for a card whose ports changed (`portLayoutKey`: its outputs — a stereo Aux's L / R, a Main Fader's …), which is left unmeasured on purpose so its ports are re-read. A port's ring changes size on hover / while wiring; `NodePort` re-reads it on `transitionend` so wires end at the ring's edge.
- The wire preview, reshape-handle and ghost SVGs (`CanvasOverlays`) are absolutely-positioned siblings of the ReactFlow div. Each is a `ViewportLayer`, which uses `useViewport()` to apply the same `translate/scale` transform as the flow canvas, so they stay aligned during pan and zoom.
- Zoom control labels are translated through ReactFlow's `ariaLabelConfig` prop (`toolbar.zoom*` keys).

### Adding a new node

Add the type's key to `TypeKey` in `src/data/nodeRegistry.ts`: every table keyed by it then fails to compile until the type is in it.

1. `NODE_REGISTRY` (`src/data/nodeRegistry.ts`): ports, category, `stereo` (a processor gets `'follow'`: it passes on stereo by itself, and reads its meters through `useStereoLevels`), `defaultParams`, `minLevel` (the easiest level whose palette shows it), `bypass` (false where the control itself is the state). Flags when they apply: `bus`, `splits`, `linked`, `freeSize` (a bare control), `minSize`
2. `PROCESS` in `src/signal/process.ts`: what it does to one channel — to every reading (`shifted` for a gain, `dynamics` for a curve; read settings with `param(node, key)`; add new keys to `ParamTypes`). A card with no power of its own goes in `PASSIVE` (no hiss); a source gets its noise in `NOISE_BELOW` and its peaks in `soundOf` / `PEAKS_ABOVE` (and a loop or a sound in `audio/`); a setting that takes one of a few words goes in `PARAM_CHOICES` (or `paramChoices` when types differ)
   - And what it does to real sound: its case in `processed()` in `src/audio/chainAudio.ts` (Web Audio nodes; a dynamics card a processor in `audio/processors.ts` with its tests, and its knobs in `settingsOf`). A card left out passes the sound on unchanged — the render then disagrees with the number engine
3. Create `src/components/nodes/YourNode.tsx` (props: `CardProps`):
   - A card → use `NodeWrapper` (`align="center"` centres a single control); its In / Out meters → `MeterSides` around its controls (they move by themselves)
   - A bare control, not a card (like Gain / Pan / Fader / Switch / Pad) → use `FreeControl`, and give it a `freeSize` in the registry
4. `NODE_COMPONENTS` in `src/components/nodes/index.ts` (its card) and `NODE_LOOK` in `src/components/nodes/nodeLook.ts` (icon, palette group — its place in that table is its place in the palette)
5. Its palette name (`palette.items`) and educational text (`theory`: `what`, `why`, `tip`) in **both** `src/i18n/locales/en.json` and `bg.json` (the build fails without them)

### Adding a new level

Add it to `ComplexityLevel` and `LEVELS` in `src/data/levels.ts`, set the `minLevel` of the types it brings in `NODE_REGISTRY`, and add its `levels.<id>` text to every locale.
